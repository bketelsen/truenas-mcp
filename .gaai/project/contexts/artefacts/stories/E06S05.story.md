# Story: Snapshot app host paths before upgrades

## User Story

**As an** AI assistant user,
**I want** app updates to snapshot the host paths where my apps keep their data,
**so that** I can recover that data if an upgrade or its data migration goes wrong.

---

## Context

`upgradeApp` called `app.upgrade` with `snapshot_hostpaths: false`, so TrueNAS snapshotted only the app's ix-volumes, and host-path data (where most apps keep theirs) could not be recovered after an upgrade. TrueNAS 25.10 middleware (`plugins/apps/upgrade.py`, `take_snapshot_of_hostpath_and_stop_app`) snapshots each host path's containing ZFS dataset as `<dataset>@ix-app-upgrade-<app>-<old version>` when the flag is true. It skips paths that are not on ZFS instead of failing. `app.rollback` (`plugins/apps/rollback.py`) restores only the ix-volumes snapshot.

---

## Out of Scope

- A tool that restores host-path snapshots or rolls an app back
- Pruning old `ix-app-upgrade-*` snapshots
- A per-call opt-out of host-path snapshots (the flag never fails an upgrade for non-dataset paths)

## Notes

Snapshots are non-recursive and never deleted by TrueNAS. A manual rollback reverts the whole dataset, including other apps' data, and destroys newer snapshots.
