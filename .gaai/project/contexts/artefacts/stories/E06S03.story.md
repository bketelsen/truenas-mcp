# Story: Expose installed app configuration as a separate read tool

## User Story

**As an** AI assistant user,
**I want** to ask the AI how an app on my NAS is configured,
**so that** I can audit environment, storage, network, and resource settings without opening the TrueNAS UI.

---

## Context

`truenas_app_get` calls `app.query` with a name filter only. TrueNAS omits the `config` object from `app.query` unless the `retrieve_config` extra is set, so the existing tool shows the running workload (containers, images, mounts, ports) but not the values entered at install or edit time. The config object can carry plaintext secrets (database passwords, claim tokens, API keys), so it is exposed through a separate tool rather than folded into `truenas_app_get`.

---

## Acceptance Criteria

- [x] AC1: A `truenas_app_config` tool returns `{ "name", "config" }` for a named app via the `app.config` API method
- [x] AC2: The tool is registered in read-only mode and its description warns that the result may contain plaintext secrets
- [x] AC3: `truenas_app_get` output is unchanged

---

## Out of Scope

- Editing app configuration
- Redacting secret fields (TrueNAS does not mark them; callers decide when to request the view)
