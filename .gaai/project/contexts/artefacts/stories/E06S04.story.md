# Story: Change installed app configuration values

## User Story

**As an** AI assistant user,
**I want** to ask the AI to change a setting on an app running on my NAS,
**so that** I can adjust ports, resource limits, or environment without opening the TrueNAS UI.

---

## Context

`truenas_app_config` (E06S03) exposes the stored configuration. TrueNAS `app.update` accepts a `values` object but merges it with a shallow top-level `dict.update` (middleware `plugins/apps/crud.py`, `update_internal`) and then back-fills schema defaults, so a partial nested payload resets every sibling in the touched section. Proven live on 25.10.4 with a throwaway `it-tools` app. The tool must therefore read the current config, deep-merge, and send the complete result.

---

## Acceptance Criteria

- [x] AC1: A write-mode-only `truenas_app_configure` tool deep-merges a partial `values` object into `app.config` output and calls `app.update` with the complete result, returning the job ID and the changed leaf paths
- [x] AC2: `ix_*` sections are refused as input and stripped from the payload; unknown top-level sections, empty values, identical values, and custom compose apps are refused before any write
- [x] AC3: `dry_run` returns the merged configuration and changed paths without calling `app.update`
- [x] AC4: Live proof on a throwaway catalog app: siblings of changed leaves survive, the app redeploys on the new port, and the tool is absent in read-only mode

---

## Out of Scope

- Custom compose apps (`custom_compose_config`)
- App installation or removal
- Waiting for the job inside the tool (callers poll `truenas_jobs_list`)
